## 0. 项目简介

本项目面向**政务办公、知识检索、业务办理和智能运维**等政企智能体应用场景，构建集 **「攻击识别、工具管控、组件检测、审计溯源」** 于一体的安全防护系统。系统可识别提示注入、越狱诱导、知识投毒等多源输入风险，对文件操作、接口调用、脚本执行等高危行为进行权限约束与动态审批，并生成可追溯审计证据，提升大模型智能体在高风险业务中的安全可控与落地应用能力。

四大能力与本系统模块对应关系：

| 能力（题目） | 本系统落地 |
| --- | --- |
| **攻击识别** | 五维 IFC 评测与运行时白名单：提示注入、越狱诱导、越权工具调用、来文投毒等对照识别与拦截 |
| **工具管控** | 场景工具白名单 + 执行门禁（文件 / 命令 / 浏览器 / 接口）+ HITL 动态审批 |
| **组件检测** | 插件 / Skill / 脚本供应链静态扫描（安装前门禁，不执行样本代码） |
| **审计溯源** | 运行时 `runtime_audit`、评测审计、`/guard` 会话证据链、JSON/Markdown 导出与审批落盘 |

**相对常见「提示词护栏 / 事后日志」方案，本系统的核心差异（详见第 2 章）：**

1. **判定依据可审计的策略白名单**，而非依赖模型自觉遵守；  
2. **五维量化评测 + 改策略可重算**，形成攻击识别闭环；  
3. **组件安装检测与来文投毒评测语义分离**，避免口径混淆；  
4. **工具执行与组件安装统一 HITL**，高危动作先审后做；  
5. **防护嵌在智能体宿主钩子内**，对话内完成审批与证据链查询；  
6. **策略 API 强制令牌 + 钩子缺令牌即阻断**，配套运维引导，便于试点落地。

## 1. 作品概述

本作品面向政务 / 企事业单位智能体落地中的三类核心风险：

1. **插件与 Skill 供应链投毒**（组件检测 / 安装前门禁）  
2. **提示注入与越权工具调用**（攻击识别：五维评测 + 运行时策略）  
3. **高危执行动作失控**（工具管控：感知—决策—调用—执行全链路门禁 + 人工审批）

系统由 **离线评测引擎** 与 **在线策略决策点（PDP）** 组成：评测阶段量化防护效果，运行时通过 OpenClaw 原生插件在工具真正执行前做允许 / 阻断 / 待审判定，并在聊天侧完成审批与证据链查询（审计溯源）。

```text
+--------------+     钩子询问      +---------------------+
|  OpenClaw    | ---------------> |  安智盾策略引擎       |
|  Agent+工具  | <--------------- |  RuntimePolicyBroker |
+--------------+  allow/block/    +----------+----------+
                  requireApproval            |
                                             v
                         攻击识别 · 工具管控 · 组件检测 · 审计溯源
                         场景白名单 · HITL · 审计落盘
```

**本服务不执行命令、不访问外网、不打开浏览器**；只返回策略结论，由 OpenClaw（或调用方）自行落地工具。

## 2. 技术创新点（重点）

本章为技术方案与答辩的**核心表述**。创新不在于「再做一个大模型」，而在于把政企智能体安全做成 **可配置、可评测、可嵌入运行时、可出证** 的工程体系。

### 2.0 创新一览（对比传统做法）

| 序号 | 创新点 | 传统常见做法 | 安智盾做法 | 对应题目能力 |
| --- | --- | --- | --- | --- |
| 1 | **策略白名单网关** | 系统提示词 / 模型自检 | YAML/JSON 规则强制判定，可 diff、可版本管理 | 攻击识别 + 工具管控 |
| 2 | **五维独立指标闭环** | 单一「拦没拦住」或人工抽检 | 数据/内容/执行/来文供应链/合规分维算 ASR·FPR，支持复现与 `--rescore` | 攻击识别 |
| 3 | **双门禁供应链分层** | 装包与来文风险混谈 | 安装期静态扫包 ≠ 办理流来文投毒评测，口径分开 | 组件检测 |
| 4 | **执行链对象化 + HITL** | 放行后难追责，或一律禁止 | 属性树/限制策略/对象头；写删与疑似安装可动态审批 | 工具管控 |
| 5 | **宿主内嵌审批与溯源** | 另建安全控制台，与对话割裂 | OpenClaw 钩子弹审批 + `/guard` 会话时间序证据链 + JSON/MD 导出 | 审计溯源 |
| 6 | **场景化最小权限可填充** | 全局一套权限或硬编码 | office/knowledge/process/ops；白名单按单位资产台账配置 | 落地适配 |
| 7 | **强制令牌与钩子覆盖加固** | 策略口匿名、缺配置仍放行 | `POLICY_TOKEN` 默认强制；插件无 `token` 则阻断钩子；运维引导同步 | 落地安全 |

### 2.1 策略白名单网关，而非「靠提示词约束」

**痛点**：提示注入、越狱诱导可诱导模型「忽略规则」；仅靠提示词无法作为审计证据。

**创新**：高危动作是否允许，由 `policies/*.yaml|json` 中的**可审计规则**决定（收件域、路径前缀、命令二进制、域名、场景工具清单等）。模型可以「想」调用危险工具，但运行时 PDP 在执行前拦截。

**价值**：判定可复现、可对比、可归档；与模型版本解耦，符合政企「策略可审」要求。

### 2.2 「评测—优化—上线」闭环，五维指标独立核算

**痛点**：智能体安全不是单一 ASR；改了规则说不清效果是升是降。

**创新**：攻击面拆为 **数据 / 内容 / 执行 / 供应链（来文） / 合规** 五维，分别计算 Baseline ASR、防护后 ASR、FPR；支持单样本复现、改策略后 `--rescore`、指标历史落盘。

**价值**：把「攻击识别」从经验判断变成**可量化、可迭代**的工程闭环：发现问题 → 改白名单 → 验证效果 → 再上线。

### 2.3 安装期与运行期双门禁，供应链语义分层（组件检测）

**痛点**：「供应链安全」常被混用：装毒插件与伪造来文诱导越权不是同一类问题。

**创新**：

| 层次 | 对象 | 模块 |
| --- | --- | --- |
| 安装期 | 已解包插件 / Skill / 脚本包 | 板块一静态扫描（**不执行样本**） |
| 办理流 | 外部来文、伪造域名、附件进入业务工具链 | 板块二 IFC「供应链（来文）」维度 |
| 运行期 | OpenClaw `before_install` | 硬风险阻断；疑似风险 **HITL 审批** 后决定是否安装 |

**价值**：组件检测口径清晰；安装与工具调用共用审批回写，形成统一人机共治入口。

### 2.4 执行链对象化门禁与动态审批（工具管控）

**痛点**：文件/命令/接口一旦放开难收回；一律禁止又无法支撑办公运维。

**创新**：对齐 AgentGate：智能体属性策略树、限制策略 puncture（deny-overrides）、任务对象头验签与派生继承；评测与运行时共用语义。高危写/删、疑似安装等可升为 **HITL**，实现「能办、可控、可追」。

**价值**：覆盖题目所述文件操作、接口调用、脚本执行等高危行为的**权限约束与动态审批**。

### 2.5 原生嵌入智能体宿主，审批与溯源在对话内完成（审计溯源）

**痛点**：另建看板导致「防护在别处、业务在对话里」，审批与证据链脱节。

**创新**：不另起独立前端。`before_tool_call` / `before_install` 返回 `block` / `requireApproval`；**未配置插件 `token` 时钩子路径默认直接阻断**（避免「有插件无鉴权」）；`/guard` 按会话输出**时间顺序证据链**；`/guard export` 一键导出 JSON 与 Markdown 到 `outputs/exports/`；审批与 `allow-always` 指纹落盘，重启不丢。

**价值**：审计证据与业务会话同轨，便于事后追责与演示「可追溯」。

### 2.6 场景化最小权限 + 策略可按单位资产台账填充

**痛点**：全局一套权限要么过松要么过紧；硬编码名单无法交付。

**创新**：内置政务办公 / 知识检索 / 业务办理 / 智能运维四场景；路径、命令、域名、邮箱域均为配置项，**可按真实单位资产填充**（仓库为对照基线，非现网清单）。

**价值**：技术方案可迁移、可定制，支撑政企落地而非一次性 Demo。

### 2.7 强制鉴权、对象头密钥与运维引导（落地配套）

**痛点**：试点时策略口常匿名开放；对象头密钥与策略文件绑死或随机不可管；场景切换与令牌同步靠口口相传。

**创新**：

- 策略 API **默认强制** Bearer（`POLICY_TOKEN`；未配置则落盘 `outputs/.policy_token`）  
- 对象头使用独立密钥 HMAC（`TCA_HMAC_SECRET` / `outputs/.tca_hmac_key`），载荷含 `kid` / `iat` / 会话·工具 `bind`  
- `scripts/ops_bootstrap.py`、`ops_sync_token.sh`：一键就绪令牌并写入 OpenClaw 插件 `config.token`  
- 使用文档提供**运维流程**与**钩子覆盖验收表**（缺 token、场景硬拦、审批、路径、安装、导出）

**价值**：从「能演示」推进到「可按清单上线试点」。

### 2.8 创新点与四大能力映射（答辩口述可用）

```text
攻击识别  ←  五维评测闭环 + 运行时白名单拦截
工具管控  ←  场景最小权限 + 执行链门禁 + HITL
组件检测  ←  静态扫包（不执行）+ 安装钩子阻断/审批
审计溯源  ←  运行时审计落盘 + /guard 会话证据链 + 导出
落地配套  ←  强制 POLICY_TOKEN + 对象头密钥 + 运维引导
```

## 3. 总体架构与数据流

### 3.1 模块一览

| 环节 | 代码 / 策略 | 职责 |
| --- | --- | --- |
| 供应链静态检测 | `src/engine/supply_chain.py` · `policies/supply_chain_policy.json` | 解包目录行为/依赖/恶意模式扫描与评级 |
| 五维 IFC 网关 | `src/engine/ifc.py` · `policies/ifc_policy.yaml` | 工具调用参数白名单、信任等级、HITL |
| 五维评测 | `src/engine/benchmark.py` · `test_docs/` | ASR/FPR、复现、重算、历史 |
| 执行门禁 | `src/engine/execution_gate.py` · `src/engine/tca.py` · `policies/execution_gate_policy.json` | 文件/命令/浏览器/API 门禁 + HMAC 对象头 |
| 运行时 PDP | `src/engine/runtime.py` · `policies/scenarios.json` | 场景路由、三引擎汇合、审批持久化、审计 |
| 证据链 | `src/engine/trace.py` | `/guard` 文本卡片、会话链与 JSON/Markdown 导出 |
| HTTP API | `src/server.py` · `run.py` | 策略与评测 API（默认 `18210`；`/v1/policy/*` 强制 Bearer） |
| OpenClaw 插件 | `plugins/gov-agent-guard/` | 钩子 + `/guard` + 审批回写；缺 `token` 默认阻断 |
| 运维引导 | `scripts/ops_bootstrap.py` · `scripts/ops_sync_token.sh` | 令牌/密钥就绪并同步插件 |

### 3.2 运行时判定流水线（单次工具调用）

1. **感知**：规范化工具名（如 `exec`→`run_command`，`write`→`write_file`）与参数别名  
2. **场景允许表**：不在当前场景 `allow` 内 → **直接阻断**（不到审批）  
3. **allow-always / 已批审批单**：同会话指纹命中 → 放行  
4. **分流引擎**  
   - IFC 工具集 → 五维白名单网关  
   - 执行工具集 → AgentGate 执行门禁  
   - 安装类 → 供应链扫描  
5. **结论**：`ALLOW` / `BLOCK` / `PENDING_APPROVAL`  
6. **落盘**：`outputs/runtime_audit.jsonl`；待审与 always → `outputs/runtime_pending.json`  
7. **回传插件**：无钩子 / `block` / `requireApproval`

### 3.3 判定语义（对业务方说明）

| 结果 | OpenClaw 表现 | 含义 |
| --- | --- | --- |
| 允许 | 继续执行原工具 | 策略通过 |
| 阻断 | 工具不执行，返回原因 | 场景禁止或硬规则失败 |
| 待审 | 弹出审批 UI | 规则允许但需人确认（如写草稿、删文件、不可信来源高危办公动作） |

## 4. 各环节说明

### 4.1 板块一：插件 / Skill / 脚本供应链安全检测

**目标**：在组件进入环境前，静态识别后门、恶意下载、隐蔽外联、依赖混淆等高危模式。

**要点**：

- 扫描对象为**已解包本地目录**，**绝不执行**样本中的脚本或安装逻辑  
- 输出动作：`ALLOW` / `REVIEW` / `BLOCK`，附评分、发现项与中文问题定位  
- 对照语料：`supply_chain_samples/` + `manifest.json`  
- 指标：恶意检出率、自动阻断率、良性误拦 FPR、期望动作准确率  

**策略可配置项示例**：规则权重、危险 API/模式、依赖混淆启发式、阻断阈值等（见 `policies/supply_chain_policy.json`）。

### 4.2 板块二：政企智能体安全评测与审计溯源（五维 IFC）

**目标**：在对照样本上量化「无防护 / 有防护」差异，并支持攻击复现与策略迭代。

**五维**：

| 维度 | 关注点（示例） |
| --- | --- |
| 数据安全 | 越权查库、导出敏感字段 |
| 内容安全 | 提示注入诱导违规外发/摘要 |
| 执行安全 | 危险命令、越权写删 |
| 供应链（来文） | 伪造发件域、恶意链接进入办理 |
| 合规 | 审批缺失、越权场景工具 |

**要点**：

- 网关实现为参数与来源标签白名单（`ifc_policy.yaml`），支持 HITL  
- `mock` 模式可无大模型密钥完成演示；`api` 模式可接 OpenAI 兼容 Function Calling  
- 审计：`outputs/audit_logs.json`；历史：`outputs/metrics_history.json`  

### 4.3 板块三：工具调用与任务执行安全约束

**目标**：覆盖「感知 → 决策 → 调用 → 执行」；对文件、命令、浏览器、接口统一鉴权。

**要点**：

- 智能体属性树（如 `agent_clerk` / `agent_admin`）与路径/命令属性绑定  
- 限制策略 puncture：拒绝覆盖允许  
- 任务对象头（落地级 HMAC-SHA256：独立密钥 / kid / iat / 会话·工具 bind；Charm/ABE **未接入**）  
- 写/删等可配置 `approval: true`，进入待审而非静默执行  
- 评测语料：`execution_samples/`；**评测过程不真实执行**  

### 4.4 运行时场景与 OpenClaw 接入

**场景**（`policies/scenarios.json`，可按单位裁剪）：

| ID | 名称 | 典型允许 |
| --- | --- | --- |
| `office` | 政务办公助手 | 邮件、日程、检索、读文件、政务域浏览 |
| `knowledge` | 知识检索问答 | 检索、读文件、政务域浏览 |
| `process` | 业务流程办理 | 办理类工具；外部来文默认待审 |
| `ops` | 运维协同助手 | 白名单命令、运维路径读写、安装扫描等 |

**插件能力**：

- `before_tool_call`：每次工具前询问策略引擎；**无 `config.token` 时直接阻断**  
- `before_install`：安装前扫描；硬风险直接阻断，疑似风险弹出审批；同样要求令牌  
- `/guard`：最近判定、待审列表、按会话 ID 的时间顺序证据链  
- `/guard export` / `GET /v1/policy/export`：导出 JSON 与 Markdown 到 `outputs/exports/`  

**安全与运维加固**：

- **强制** `POLICY_TOKEN`：`/v1/policy/*` 需 Bearer；未配置则自动落盘 `outputs/.policy_token`  
- 插件 `token` **必须**与引擎一致；`python scripts/ops_bootstrap.py --sync-openclaw` 一键同步  
- `failClosed`（默认 true）：引擎不可达则阻断工具  
- 对象头独立密钥：`TCA_HMAC_SECRET` 或 `outputs/.tca_hmac_key`  
- 钩子覆盖边界：仅保护经 OpenClaw 上述钩子的调用；验收表见《使用文档》§6.3  
- 审计轮转（默认保留最近约 2000 条运行时记录）

## 5. 使用方法

### 5.1 环境准备

```bash
cd <项目根目录>
python -m pip install -r requirements.txt
# 建议：复制 .env.example 为 .env，设置 PORT / POLICY_TOKEN / TCA_HMAC_SECRET / LLM_*
python scripts/ops_bootstrap.py --show   # 确保令牌与对象头密钥就绪
```

### 5.2 启动策略引擎（在线门禁必需）

```bash
python run.py
# 默认 http://127.0.0.1:18210
```

健康检查：`GET /api/health`（应见 `policy_token_required=true`）。

### 5.5 对话内操作

```text
/guard                 # 最近运行时判定
/guard pending         # 待审批单
/guard <会话或事件ID>   # 会话时间序证据链或单条卡片
/guard export [id]     # 导出 JSON + Markdown 到 outputs/exports/
```

待审时在 OpenClaw Control / 频道按钮 / `/approve` 中选择允许或拒绝；`allow-always` 会写入会话级指纹。

**弹窗条件**：宿主必须实际发起对应工具调用，且策略返回 `requireApproval`。  
仅有 `exec`、无写文件工具时，无法演示「写文件待审」；可改场景为 `ops` 并对允许的路径使用 `write`，或用下方 HTTP 自测。

### 5.6 无 OpenClaw 时的 HTTP 自测

策略接口需带 Bearer（令牌见 `outputs/.policy_token` 或 `.env`）：

```bash
TOKEN=$(cat outputs/.policy_token)   # Linux/WSL；Windows 可用 Get-Content

# 场景阻断示例（office 禁 shell）
curl -s -X POST http://127.0.0.1:18210/v1/policy/check \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"tool":"exec","args":{"command":"whoami"},"scenario":"office","session_id":"demo-1"}' \
  | python -m json.tool

# 待审示例（ops + 写草稿路径）
curl -s -X POST http://127.0.0.1:18210/v1/policy/openclaw/before-tool-call \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"toolName":"write","params":{"path":"/office/drafts/memo.docx","content":"demo"},"scenario":"ops","sessionId":"demo-2"}' \
  | python -m json.tool
```

期望：前者 `allowed=false`；后者 `action=approve` 且含 `hook.requireApproval`。

## 8. 边界与诚实说明（答辩建议主动说明）

1. **TCA 密码学**：运行时为独立密钥的 HMAC-SHA256 对象头（含 kid/iat/业务 bind）；Charm/ABE 实验实现**未接入**当前 PDP，亦不纳入比赛源码包。生产请配置 `TCA_HMAC_SECRET`。  
2. **策略引擎不执行工具**：安全性依赖「先问后做」；**未经过** OpenClaw `before_tool_call` / `before_install` 的通道不在本系统防护范围内。  
3. **钩子覆盖已加固但仍有边界**：缺插件 `token` 会阻断钩子路径；但未装插件、其它宿主或直连执行仍不受控——需运维保证高危能力只经本插件。  
4. **安装待审依赖宿主**：`before_install` 已返回 `requireApproval`；若客户端未实现安装审批 UI，可能需在 Control 侧确认。硬拦截（`BLOCK`）仍直接拒绝安装。  
5. **三套评测语料与单一在线 Agent 循环仍相对独立**：完整串联按《使用文档》组织评测与 OpenClaw 演示。  
6. **宿主工具集决定可演示能力**：无邮件/删文件工具时，对应路径用 HTTP 或改用已有工具（如 `write`）演示审批。

## 9. 答辩演示建议脚本（约 8–10 分钟）

1. **开场（创新总括，约 1 分钟）**：安智盾不是再做一个大模型，而是「白名单 PDP + 五维可量化评测 + 宿主内嵌审批溯源」；相对提示词护栏，判定可审计、效果可复算、证据在对话内可查。  
2. **创新对照表**：快速过第 2.0 节对比（含强制令牌与运维引导）。  
3. **跑 `run_eval.py --mode mock`**：展示五维 ASR/FPR 与单样本复现（攻击识别闭环）。  
4. **跑供应链评测**：强调静态、不执行恶意样本；安装疑似包可走审批（组件检测）。  
5. **跑执行门禁评测**：展示属性树、HMAC 对象头与审批类任务（工具管控）。  
6. **运维一笔带过**：`ops_bootstrap` 同步令牌；说明缺 token 钩子即拦。  
7. **打开 OpenClaw**：`office` 下 shell → 场景阻断；`ops` 下 `write` 草稿 → 审批弹窗；`/guard` / `export`（审计溯源）。  
8. **收尾**：打开策略 JSON/YAML，说明可按单位资产台账填充；回扣四大能力 + 落地配套（第 2.8 节）。
